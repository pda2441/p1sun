# API и интеграция

Авторский локальный скилл. Вход: сценарий, существующие клиент и сервер, роли доступа, границы внешних операций.

1. Проследить действие → запрос → операция → результат. Разделить реальный сервис и явно помеченный мок. Не добавлять backend без потребности.
2. До раздельной реализации согласовать `docs/api.md`: методы/пути, обязательные поля и типы, успешные ответы, ошибки, авторизацию, права на ресурс, пагинацию и повтор запросов по необходимости. Выбрать единый формат ошибки: код, безопасное сообщение, ошибки полей, идентификатор запроса.
3. Реализовать серверную проверку ввода и прав. Определить сессии/токены и требования CSRF/CORS по архитектуре. Не возвращать секреты и внутренние исключения клиенту.
4. Связать UI с настоящим ответом: ожидание, успех, ошибка поля, отказ доступа, недоступность сети, пустой результат. Исключить опасные дубликаты повторной отправки; где нужно, добавить идемпотентность.
5. Проверить валидный и неверный ввод, отсутствие авторизации, чужой ресурс, повтор и отказ сервера. Перечитать сохранённые данные. Не выполнять внешние сообщения/платежи без отдельной задачи.

Результат: контракт, согласованные реализации, команды и фактические ответы без секретов. Завершено, когда основной путь и значимые отказы дают согласованное поведение; неподключённые части явно обозначены.
