# Fullstack-приёмка

Авторский локальный скилл. Вход: бриф, критерии, запуск, тестовые данные и границы внешних действий. Для визуальной оценки использовать visual-quality-review.

1. Изучить архитектуру и составить матрицу: действие → ожидаемый UI → запрос/операция → сохранённый результат. Статическому сайту API/БД отметить «не применимо».
2. Выполнить доступные проверки README: команды, версии и коды завершения записать. Сборка сама по себе не доказывает работу сценария.
3. Пройти основной путь в реально запущенном приложении. Сверить UI и API, перечитать данные новым запросом/после перезагрузки. Пользоваться изолированными тестовыми записями. Реальные платежи и внешние сообщения требуют отдельной задачи.
4. Проверить неверный ввод, пустые данные, отсутствие прав, чужой ресурс, повтор, сетевую и серверную ошибку по значимости. Локальный toast не доказывает успешную отправку.
5. Проверить Tab, видимый фокус, Enter/Space, Escape и возврат фокуса диалога; подписи полей, доступные имена, ошибки и заголовки.
6. Для публичных страниц проверить title, description, язык, заголовки, ссылки и 404; canonical/robots/sitemap — по архитектуре. Проверить отсутствие случайного запрета production-индексации.
7. После исправлений повторить затронутые и смежные сценарии. Не создавать бессодержательные тесты ради количества.

Результат `docs/qa-report.md`: сценарий, ожидание, факт, PASS/FAIL/NOT RUN/не применимо, доказательства и шаги воспроизведения. Завершено, когда критерии проверены, существенные дефекты исправлены либо явно остались открытыми.
