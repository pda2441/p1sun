# Восстановление WW KiMa

Сохранить всю папку проекта, включая скрытые `.agents`, `.codex`, `.gitignore`, локальные `assets`, документы и lock-файлы. Node и браузер являются программами среды, а не частью исходников. Процессы и системный PATH архивом не восстанавливаются. Секретов и БД у проекта нет.

1. Восстановить проект в обычную рабочую папку. Прежнее имя пользователя и абсолютный путь не требуются.
2. Установить Node.js 24.22.1 LTS с официального источника. В архиве всего my-projects есть переносимый `tools/node/node.exe`; для отдельного клона установить Node самостоятельно. npm-пакеты для сайта не требуются.
3. Из корня сайта выполнить `node scripts/verify.mjs`, затем `node scripts/server.mjs` и открыть http://127.0.0.1:4173/.
4. Проверить меню, диалог с Escape и возвратом фокуса, мобильную навигацию и честное сообщение демоформы. Полный browser QA описан в docs/qa-report.md.
5. При занятости порта остановить собственный предыдущий сервер или выбрать PORT. Не завершать незнакомые процессы. Сервер слушает только 127.0.0.1.

Происхождение скиллов — docs/skills-lock.json; неизменяемые файлы — docs/site-kit-manifest.json. `scripts/Test-SiteKit.ps1` сохранён без изменений. В текущей среде запуск ps1 запрещён политикой PowerShell (`UnauthorizedAccess`, running scripts is disabled). Не менять ExecutionPolicy/ACL ради обхода. Node проверяет файлы независимо от ps1.

При первой разработке установка `@playwright/cli` и `sharp` не удалась: npm registry ETIMEDOUT даже после разрешённого сетевого повторения. Проект работает без них. Изображения подготовлены через штатный System.Drawing, browser QA — через установленный Edge и CDP. Это документированные адаптации инструментов, исходные скиллы не менялись.

Перед Deep Freeze остановить сервер и проверочный браузер, записать прогресс, сделать ZIP всей my-projects вне сбрасываемого диска и проверить распаковку, локальные ресурсы и скрытые инструкции. Папка coffe не изменяется.
