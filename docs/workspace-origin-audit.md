## Значение статусов

- **Скачан**: файлы получены из первичного источника. Для авторского скилла — «создан локально».
- **Установлен**: полный пакет находится в `.agents/skills/<фактическое-name>`.
- **Обнаружен**: установленный Codex вернул пакет в локальном `skills/list`; это не равно успешному выполнению сценария.
- **Зависимости доступны**: есть нужные программы, доступ и при необходимости авторизация.
- **Выполнение проверено**: сценарий скилла реально выполнен. При подготовке сайтов и внешних интеграций нет; такой проверки не заявляем.

## Особенности Windows и адаптации

Смысл сторонних SKILL.md не менялся. Их общие правила применяются в рамках поручения пользователя и политик текущего клиента.

- Playwright использует Bash, npx и `$CODEX_HOME/skills/playwright`; здесь пакет расположен в `.agents/skills/playwright`. После установки зависимостей в Bash путь указывать относительно корня сайта: `PWCLI="$PWD/.agents/skills/playwright/scripts/playwright_cli.sh"`. CODEX_HOME ради этой обёртки менять не требуется. Это документированная адаптация команды, не правка upstream. Windows-эквивалент `npx --package @playwright/cli playwright-cli` требует отдельной проверки; сейчас не запускался.
- web-design-guidelines требует свежий `https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md` и средство WebFetch. Без сетевого получения свежих правил нельзя объявлять полное выполнение этого скилла. Проверка кода дополняется локальным visual-quality-review для внешнего вида.
- gh-address-comments требует elevated network access и обращений к PR; текущая политика не позволяет эскалацию файлового/sandbox-доступа. Не обходить ограничение. gh-fix-ci содержит отдельный шаг согласования исправлений; учитывать уже данную явную задачу, не требовать повторного разрешения на ту же локальную работу.
- security-threat-model предусматривает уточнение существенных предположений до итогового отчёта. Security-скиллы не включать автоматически в любой несвязанный review.
- В `gh-address-comments/agents/openai.yaml` upstream оставляет завершающую кавычку в plain scalar short_description. Файл сохранён как есть; установленный клиент обнаружил скилл без ошибок. Это не подтверждает качество UI-метаданных во всех клиентах.

Не устанавливались npm-пакеты, БД или инфраструктура под ещё не выбранный стек. При восстановлении сначала проверять доступность конкретного инструмента.

## Проверки комплекта

`Test-Workspace.ps1` создан для PowerShell 5.1, определяет корень по своему пути, читает явный manifest, не обращается в сеть и не меняет файлы. Проверяет ресурсы и SHA-256, метаданные, имена, установленные копии и отсутствие общего Git-репозитория. Код 0 — всё проверенное PASS; 1 — обнаружен FAIL.

Его реальный запуск заблокирован политикой PowerShell: `running scripts is disabled on this system`, `FullyQualifiedErrorId: UnauthorizedAccess`, код 1. Set-ExecutionPolicy, Bypass и выполнение текста скрипта в обход не использовались. Для запуска нужен разрешённый политикой способ исполнения доверенных/подписанных скриптов, который предоставляет пользователь или администратор. Простая подпись без доверенного сертификата это не исправляет.

Пять PowerShell-файлов разобраны штатным Parser без исполнения: синтаксических ошибок 0. Их поведение, включая New-Site, не объявляется проверенным. Отдельный read-only `Check-Workspace.py` выполнил проверку manifest в Python: **67 PASS, 10 FAIL**; десять FAIL — отсутствие пяти установленных авторских пакетов и пяти корневых определений агентов. JSON и семь TOML разобраны. Браузер и DeepSeek API не запускались.

Python-аудитор проверен на изолированной копии: 4/4 проверки ожидаемой незавершённости, повреждения ресурса, отсутствующего файла и небезопасного пути прошли. Это проверка самого Python-аудитора, а не исполнения ps1; сведения в `checker-validation.json`. Полный актуальный вывод аудита — `verification-report.txt`.

Поддержка версий: `Build-WorkspaceManifest.py` — осознанная операция сопровождающего после review изменений, а не шаг проверки. Не перегенерировать хеши, чтобы скрыть повреждение. `New-Site.ps1` переносит только выбранные пакеты и их происхождение, отказывается перезаписывать существующий сайт. Для изменения уже перенесённого скилла сначала сравнить diff и старые SHA-256, затем обновить осознанно; автоматического overwrite нет.
